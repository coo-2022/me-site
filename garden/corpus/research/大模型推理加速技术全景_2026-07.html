大模型推理加速技术全景

调研日期:2026-07-05 · 前篇:[大模型推理加速技术调研_2026-07]

生产可用性评级:★★★ 生产默认/主流框架内置 · ★★ 生产可用但需针对性评估 · ★ 前沿/实验阶段

0. 技术地图总览

推理加速的全部手段,按”改什么”分为九类:

① 模型压缩      改权重/激活的数值表示与数量(量化、剪枝、蒸馏)
② 模型架构      改模型本身的计算图(GQA/MLA、SSM 混合、MoE、稀疏注意力、MTP)
③ 解码算法      改 token 的生成方式(投机解码、扩散解码)
④ 运行时调度    改请求的组织方式(batching、KV 管理、PD 分离、缓存复用)
⑤ Kernel/编译   改单个算子的执行效率(FlashAttention、FP8 GEMM、CUDA Graphs)
⑥ 并行策略      改模型在多卡上的切分方式(TP/PP/EP/SP)
⑦ 长上下文专项  专攻 KV cache 的显存与带宽瓶颈(驱逐、压缩、offload)
⑧ 硬件          换执行的芯片(Blackwell、ASIC)
⑨ 框架          上述手段的工程集成(vLLM/SGLang/TRT-LLM/llama.cpp)

物理约束不变:prefill 算力受限(决定 TTFT),decode 带宽受限(决定 TPOT)。每项技术本质上都在攻其中一个,或者攻”重复计算”(缓存复用类)。

① 模型压缩

1.1 权重量化(weight-only)

机制:只压权重不压激活,decode 阶段权重搬运量减半/减 3/4,直接提升带宽受限下的 TPOT。

方案代表工作收益评级
INT4 权重(GPTQ)GPTQ (arXiv:2210.17323)权重 4×压缩,7B 模型单卡 8GB 可跑★★★
INT4 权重(AWQ)AWQ,激活感知选保护通道同 4×,精度普遍优于 GPTQ,vLLM/TRT 均内置★★★
FP8 权重+激活H100 原生支持显存减半,精度损失 <1%,当前生产默认★★★
NVFP4 / MXFP4Blackwell 原生 4bit 浮点相对 FP8 再减半,官方称精度损失 <1%(NVIDIA 自报)★★

1.2 激活量化(W8A8 / W4A4)

机制:激活也量化,矩阵乘直接用低精度 Tensor Core,prefill 也加速(纯 weight-only 只加速 decode)。

方案代表工作收益评级
W8A8 SmoothQuant把激活离群值”迁移”到权重INT8 全程,吞吐 ~1.5×,精度接近无损★★★
W4A4QuaRot/SpinQuant 旋转消离群值理论 4×算力,精度仍有损,Blackwell W4A4KV4 路线★

1.3 KV cache 量化

机制:KV 从 FP16 → FP8/INT4,同显存下 batch 或上下文翻倍~4 倍。FP8 KV 生产成熟(★★★),NVFP4 KV 在 Blackwell 上再减半、官方称损失 <1%(★★)。

1.4 剪枝 / 稀疏

机制:把部分权重置零;2:4 半结构化稀疏(每 4 个连续权重恰好 2 个零)可用 Ampere+ 的 Sparse Tensor Core 硬件加速。

方案代表工作收益评级
一次性剪枝(需校准数据)SparseGPT (arXiv:2301.00774)50% 稀疏免重训,质量优于 Wanda,适合出产线 checkpoint★★
一次性剪枝(免校准,快)Wanda (arXiv:2306.11695)权重×激活范数打分,开销远低于 SparseGPT,适合快速迭代★★
2:4 硬件稀疏推理vLLM + Sparse Tensor Core线性层 ~1.6×,端到端仅 1.24–1.27×(LLaMA-7B 实测)★★

注意:剪枝的端到端收益明显小于量化(attention/非线性部分不受益),且质量损失更难控,生产采用率远低于量化。这是”论文数字漂亮、落地折扣大”的典型区。

1.5 蒸馏(结构性压缩)

机制:大模型当教师,小模型当学生;NVIDIA Minitron 路线 = 结构化剪枝(宽度 > 深度)+ 蒸馏恢复精度。

  • Llama-3.1-8B → Minitron-4B、Mistral-NeMo-12B → 8B:相比从头训练小模型,MMLU +16%,训练 token 需求降 40×(约 100B tokens/模型)(NVIDIA, arXiv:2408.11796)。评级 ★★(需要训练资源,推理侧收益 = 直接换小模型)。
  • 宽度剪枝精度更好,深度剪枝同参数量下延迟更低——按 SLO 选。

② 模型架构(训练时就决定的加速)

2.1 注意力头共享:GQA → MLA

方案机制收益评级
GQA多 query 头共享一组 KV 头KV cache 减 4–8×,Llama-2 70B 起业界标配★★★
MLAKV 低秩压缩为 latent 向量(DeepSeek-V2/V3)KV cache 相对 MHA 减 ~5×+,且精度优于 GQA★★★(新模型)

2.2 线性注意力 / SSM 混合架构

机制:Mamba 类 SSM 层的”KV”是固定大小状态,不随序列长度增长;混合架构按 ~7:1 混入少量 attention 层保住精度。

  • Jamba(AI21):Mamba:Attention ≈ 7:1 + MoE,52B 总参/12B 激活,256K 上下文,长序列吞吐最高 ~3–5× 同规模 Transformer、显存占用大幅低(AI21, ICLR’25)。
  • 同显存预算可开更大 batch → 直接降低每请求服务成本。2025 年后 NVIDIA Nemotron-H、IBM Granite 4.0 等相继采用混合路线。
  • 评级 ★★:架构本身成熟,但生态(投机解码、prefix caching 等与 SSM 状态的兼容)仍在补课。

2.3 MoE(稀疏激活)

机制:每 token 只激活少数专家,推理 FLOPs 按激活参数算(DeepSeek-V3 671B 总参/37B 激活)。加速本质是”同能力下少算”,代价是显存仍要装下全部专家 + EP 并行通信。评级 ★★★(前沿模型主流形态)。

2.4 稀疏注意力(训练原生)

机制:attention 只算被选中的 block,而且从预训练起就稀疏(区别于推理期近似),长上下文的 prefill 和 decode 同时受益。

方案代表工作收益评级
NSA(层次压缩+块选择+滑窗三分支)DeepSeek (arXiv:2502.11089)64K 序列:前向 ~9×、反向 ~6×(vs FlashAttention-2),精度持平或更好★★
MoBA(块级 MoE 路由注意力)Kimi/Moonshot,已在 Kimi 生产长序列处理最高 ~5×,已有生产验证★★
DSA(轻量索引器选 token)DeepSeek-V3.2长上下文 API 成本降约一半(官方降价折算)★★

2.5 多 token 预测(MTP)

机制:训练时加轻量头预测未来第 2+ 个 token,推理时天然充当”自带草稿模型”做投机解码。

  • DeepSeek-V3:第二 token 接受率 85–90%,换来生成吞吐 ~1.8×(DeepSeek-V3 Tech Report)。GLM-4.5/GLM-5 同样采用。
  • 评级 ★★★(对采用了 MTP 的模型是免费加速;旧模型无法追加)。

③ 解码算法

3.1 投机解码谱系

机制:便宜的”草稿”猜 N 个 token,目标模型一次前向并行验证,输出分布严格无损。

方案草稿来源收益评级
独立小模型草稿原始 speculative decoding~2×,但要维护配套小模型★★
Medusa(多解码头)模型自带多头~2.2–2.8×,有损变体需谨慎★★
EAGLE-3特征层自回归草稿头接受率 0.80–0.88,2–6.5×(batch 越小越赚),vLLM/SGLang 内置★★★
MTP 复用(见 2.5)训练时自带~1.8×,零额外组件★★★
Prompt lookup / n-gram从上下文里抄免训练,改写/摘要类任务 2–4×,通用任务无效★★★(特定场景)
LongSpec长上下文专用草稿>32K 场景仍保持加速(普通草稿头此时失效)★

关键工程事实:投机解码收益与 batch size 负相关——大 batch 下 GPU 已被填满,验证的并行度红利消失。在线低延迟场景最赚,离线大吞吐场景可能为负收益。

3.2 扩散语言模型(换掉自回归本身)

机制:所有 token 一次生成、多轮去噪并行精化,彻底绕开逐 token 串行瓶颈。

  • Mercury 2(Inception Labs,2026-02):~1,009 tok/s(Blackwell),约为速度优化过的自回归模型的 5×;复杂推理基准落后 5–15%,结构化输出/翻译类任务持平(BusinessWire, arXiv:2506.17298)。
  • Gemini Diffusion(Google,2025-05):~1,479 tok/s,约 5× Gemini 2.0 Flash Lite;字节 Seed Diffusion 同路线(arXiv:2508.02193)。
  • 评级 ★:速度数字惊人,但质量差距和生态(工具调用、流式、缓存)未收敛。值得跟踪,暂不押注。

API 侧对应物:context caching 定价

供应商把 prefix caching 直接产品化:Anthropic cache 读取按 0.1× input 价、DeepSeek 缓存命中约 1/10 价、Gemini 有显式 context caching。对 agent 类长系统提示词负载,账单层面就是 5–10× 降本——这是普通用户能”免费”吃到的推理加速。评级 ★★★。

⑥ 并行策略

策略切什么适用关键约束
TP 张量并行单层矩阵切列/行单机 8 卡内,降延迟首选每层两次 all-reduce,跨机即死于通信
PP 流水并行按层切段跨机扩容bubble 浪费,batch 要够大
EP 专家并行MoE 专家分卡DeepSeek/GLM 类 MoE 必需all-to-all 通信,负载均衡是命门
SP 序列并行按序列维切超长上下文 prefill与 attention 实现耦合深
DP attentionattention 部分数据并行(SGLang 对 MLA 的做法)MLA 模型:KV 太小,TP 切 KV 反而浪费模型结构特定

经验法则:单机内 TP,跨机 PP,MoE 加 EP,长文加 SP;并行是”装得下/够快”的手段,本身不减少计算量。评级整体 ★★★(框架内置)。

⑦ 长上下文专项(KV cache 三条战线)

KV cache 是长上下文唯一的敌人:128K 上下文的 70B 模型,KV 可以比权重还大。

战线方案机制与收益评级
量化FP8/INT4 KV(见 1.3)2–4×,质量最稳★★★
驱逐StreamingLLM(sink+滑窗)、H2O(累积注意力分选 heavy-hitter)、SnapKV(观察窗内池化打分,prefill 后即压)、R-KV保 10–50% token,heavy-hitter 类在推理基准上显著优于其他驱逐法、偶尔反超全量 KV;但对推理型长思维链更脆弱,压缩率要保守★★
检索式稀疏Quest(按 query 动态选相关 KV 页,不真删)自注意力带宽降数倍且无信息永久丢失,长文 decode 加速 2–7×(论文数)★★
下沉LMCache/Mooncake(见 ④)显存装不下就分层存储★★

选型直觉:先量化(无脑),再检索式稀疏(不丢信息),驱逐类最后用且对 CoT 模型要格外小心。

11. 判断与展望

  1. 量化是回报率之王:FP8 已是默认,NVFP4 是 2026 主升浪;剪枝论文多落地少,蒸馏本质是”造小模型”而非加速手段。
  2. 架构红利在向训练侧前移:MLA、NSA/MoBA、MTP 都是”训练时就把推理账算好”——推理加速正在从 serving 团队的事变成预训练团队的事。这与 GLM-5 / DeepSeek 的实践一致。
  3. 投机解码进入”模型自带”时代:独立草稿模型 → EAGLE 头 → MTP 内置,外挂式加速被吸收进模型本体。
  4. KV cache 是长上下文时代的中心战场:量化/驱逐/检索稀疏/分层存储四线并进,LMCache 生产毕业标志着”KV 即资产”的基础设施化。
  5. 扩散 LM 是唯一可能改写游戏规则的变量:1,000+ tok/s 是数量级差异,盯 Mercury/Seed Diffusion 的质量收敛速度。
  6. 用三元组框架看:这套体系的衡量标准已经统一为 goodput(SLO 达标吞吐)+ $/M tokens,谁的评估器快、谁能自动搜索配置空间(参见 AlphaEvolve 一节的讨论),谁就能持续吃到组合红利。
