从垂域数据到训练集:业界数据清洗与合成方法调研

调研日期:2026-07-06 · 场景:问题工单、内部文档、规范制度等存量垂域数据 → SFT/CPT 训练集

0. 结论先行

  1. 管线形态业界已收敛:解析归一 → 清洗 → 脱敏 → 去重 → 质量过滤 → 合成扩增 → 合成质检 → 数据选择 → 评测,每一环都有成熟开源件,不需要自研框架。
  2. 合成是垂域的必经之路:工单/文档本身不是训练样本,必须经过”转写”(文档→QA、工单→对话)才能变成 SFT 数据;直接拿原文做 SFT 是最常见的错误。
  3. 质量 > 数量已被反复验证:LIMA/DEITA 证明精选 6K 样本可打平 125K 随机样本——垂域数据量少不是问题,质检不严才是问题。
  4. 先建评测集再造训练集(三元组:衡量标准先行):从存量数据里先抠出 200–500 条人工确认的 held-out 业务测试题,它决定后面所有环节的取舍。

1. 总体管线

原始垂域数据(工单/文档/规范)
  │ ①解析归一:PDF/HTML/工单系统 → 干净文本+结构元数据
  │ ②清洗:规则过滤(长度/乱码/模板噪声)+ 模型质量分类器
  │ ③脱敏:PII/敏感信息识别与替换
  │ ④去重:精确(hash)+ 模糊(MinHash LSH)+ 与评测集去污染
  │ ⑤合成:文档→QA / 工单→对话 / 规范→判定任务
  │ ⑥合成质检:verifier 拒绝采样 + LLM-as-judge(锚定原文)+ 再去重
  │ ⑦选择与配比:质量×多样性×难度打分,混入通用数据防遗忘
  ▼
SFT/CPT 数据集 + held-out 评测集

2. 清洗(Cleaning)

2.1 规则启发式(第一道粗筛)

语言识别、长度/重复率/符号比阈值、模板噪声剥离(工单里的签名/免责声明/系统自动回复)。C4/Gopher/RefinedWeb 规则集是事实标准,各框架均内置。成本近零,先跑掉 30–50% 垃圾。

2.2 模型质量分类器(第二道精筛)

FineWeb-Edu 范式:用强模型(Llama3-70B)给样本打质量分 → 训练小分类器 → 全量打分过滤(emergentmind 综述)。垂域落地时把”教育价值”换成业务标准:“这条工单的解决方案是否完整可复现""这段文档是否包含可操作的事实”。

关键教训(直接抄作业可少踩坑):

  • FineWeb-Edu 激进过滤掉 ~90% 原始数据,后来 Nemotron-CC 发现这牺牲了多样性,改为:放宽启发式 + 分类器集成投票 + 对低质数据做合成改写(rephrase)而非直接扔(NVIDIA Nemotron-CC 管线)。
  • 分类器并不可靠:复检发现 FineWeb-Edu 分类器约 7% 的判定会自我反转(arXiv:2605.23721)——阈值附近的样本要人审抽检,别全信分数。

2.3 去重与去污染

  • 精确去重(MD5/SHA)+ 模糊去重(MinHash + LSH,13-gram、相似度 0.8 是常用起点)+ 子串去重(suffix array)。
  • 去污染(decontamination):训练集必须与自建评测集做 n-gram 重叠检查,否则评测数字全是假的。垂域尤其危险——同一张工单的不同副本极易同时落进训练和测试。

3. 脱敏(PII / 敏感信息)

工单是重灾区:客户姓名、账号、电话、内部系统 ID。训练数据里的 PII 会在无关问题中被模型吐出来,是合规硬风险(Limina)。

三级方案,按敏感度递进:

级别方案说明
L1 正则邮箱/电话/证件号/密钥 pattern → 占位符成本最低,召回有限;“宁可误杀”策略(本档案库 ingest/archive_claude_chats.py 即此路线)
L2 NER 模型Presidio 类工具 + 领域词表覆盖人名/机构名等正则抓不住的
L3 微调专用模型微调 7B 级模型做上下文感知脱敏,Mistral-7B 可达 BLEU 0.911 / 精确率 0.962(arXiv:2512.18608)研究显示上下文感知的脱敏基本不损伤下游任务性能,比无脑挖空好

原则:用一致的假名替换(同一客户全程映射到同一化名)而非 [REDACTED],保住对话的指代结构;阈值附近样本留人审通道。

4. 合成(Synthesis):把垂域数据”转写”成训练样本

4.1 方法谱系

方法机制适用出处
Self-Instruct人写种子任务 → LLM 仿写扩增有少量人工标注样例时冷启动arXiv:2212.10560
Evol-Instruct对已有指令做深化/泛化”进化”提升难度与复杂度覆盖WizardLM
Magpie只给对齐模型一个前缀模板,让它自吐指令免种子、多样性覆盖最广;但数学/代码类分布不足arXiv:2406.08464
Bonito专训的”任务生成模型”:无标注文本 → (指令,答案) 对文档/规范 → QA,专为私有垂域设计,支持是非/抽取式 QA/NLIarXiv:2402.18334
RAFT 式文档 + 干扰文档 → 带引用的 CoT QA训”结合检索回答”能力,配合 RAG 部署效果最好RAFT (Berkeley)
指令回译拿现成高质量文本反推”什么指令会产出它”工单的优质回复 → 反推用户问题Self-Alignment 系
Persona Hub用海量人设(1M+ persona)当多样性引擎同一文档从”新手客服/资深工程师/审计员”多视角出题腾讯,Nemotron-Personas 跟进

对比数据:Magpie 微调效果显著优于 Self-Instruct,其 t-SNE 分布覆盖了 Alpaca/Evol-Instruct/UltraChat 的全部区域(论文)。

4.2 按数据类型的具体配方

工单 →

  • 已解决工单 → (用户问题, 排查步骤, 解决方案) 多轮对话 SFT;保留真实的追问-澄清轮次,这是垂域最稀缺的对话结构。
  • 聚类相似工单 → FAQ 蒸馏(SC’25 已有用 LLM 从技术支持工单自动生成 FAQ 的工作,ACM)。
  • 未解决/低质工单不要浪费:可以当负例训 reward model,或当”疑难征集”用 Evol-Instruct 升难度。

文档 →

  • RAFT 式:每篇文档切 chunk,生成”需要引用原文才能答对”的 QA,并混入干扰 chunk——模型学会引用而非幻觉。
  • 大体量文档(百万 token 级)可另做 CPT(继续预训练)语料:只清洗不转写,训完再上 SFT。经验阈值:垂域语料 < 1B token 时 CPT 收益有限,优先 SFT。
  • CPT 必须混入通用数据回放(replay)防灾难性遗忘,垂域:通用 从 1:1 到 3:7 起步搜索。

规范/制度 →

  • 条款 → 判定任务:“以下工单处理过程违反了哪条规范?”——答案可程序化校验,天然适合后续做 RLVR(可验证奖励强化学习,衔接 本机RL训练方案_2026-07 的 reward 设计)。
  • 规范条文之间做交叉出题(条款 A 与 B 冲突时如何处理),覆盖真实的边界 case。

5. 合成数据质检:防”合成垃圾”与模型坍缩

合成不设质检 = 把种子模型的偏差放大注入。四道闸:

  1. 拒绝采样:有标准答案的(规范判定、可执行步骤)用 verifier/规则校验,MetaMathQA 用最终答案正确性过滤、代码类用执行结果过滤——这是最硬的信号。
  2. LLM-as-judge 锚定原文:让 judge 对照源文档评”是否忠实/是否可从原文推出”,研究表明接地(grounded)的过滤 + 定向重生成比裸 judge + 简单重采样的产出率更高(arXiv:2606.11127)。judge 打分维度参考 DEITA:复杂度/质量/多样性三轴。
  3. 再去重:合成数据内部重复率远高于自然数据(同一 chunk 生成的 QA 高度相似),MinHash 再跑一遍。
  4. 真实数据混合:纯合成数据迭代训练会坍缩;保留真实工单对话原样样本、让真实数据覆盖分布尾部,是已验证的缓解手段(arXiv:2502.08924)。

6. 数据选择与配比:少即是多

  • LIMA:1K 精选样本对齐即可用——质量压倒数量。
  • DEITA:复杂度×质量×多样性三维打分选 6K 样本,打平/超过 125K 随机样本训练的 Vicuna(arXiv:2312.15685,distilabel 已内置该管线)。
  • IFD(指令跟随难度):挑”模型学起来费劲”的样本优先训,补短板。
  • 实操顺序:全量合成 → 三维打分 → 分桶(按任务类型/难度)分层采样 → 小规模训练验证 → 按评测短板回补对应桶。垂域 SFT 最终落在 5K–50K 高质样本是常见区间,不必追求百万级。

8. 落地蓝图(两周可验证)

  1. D1–2 建衡量标准:人工从工单/文档抽 300 条真实问题做 held-out 评测集(答案人工确认),同时定义 judge 评分 rubric。没有这一步,后面全部工作无法证明有效。
  2. D3–5 清洗+脱敏:Data-Juicer 规则粗筛 → MinHash 去重 → Presidio+正则脱敏 → 与评测集去污染。
  3. D6–9 合成:文档走 RAFT 式 QA,工单走对话重构,规范走判定任务;persona 增广多样性;每类先出 2–3K。
  4. D10–11 质检+选择:verifier + 接地 judge 双闸 → 再去重 → DEITA 三维打分留 top 50–70%。
  5. D12–14 小模型验证:7B 级 LoRA SFT,对比 base 模型在 held-out 集上的提升;按短板回补数据。产出:数据管线一套 + 第一版数据集 + 提升曲线。

9. 判断

  1. 清洗是搬运,合成是创造,评测是方向盘——三者投入比大致 2:5:3,多数团队把 8 成力气花在清洗上,方向反了。
  2. 垂域数据的核心价值不在文本本身,而在结构(工单的”问题→排查→解决”因果链、规范的可判定条款)——转写方法保住结构,数据就成了;丢了结构,再多 token 也白搭。
  3. 规范类数据是被低估的宝藏:可程序化验证 = 可做 RLVR = 从 SFT 直通强化学习,和 AReaL_2.0_自演进能力解读_2026-07 的”真实轨迹回流”接上就是完整的自演进闭环:工单持续产生 → 管线自动转写 → 训练 → 部署 → 新工单。
  4. 用三元组检验这套体系:数据化(存量工单文档)✓、元能力(合成与质检管线)✓、衡量标准(held-out 业务评测集)——第三项最容易被省略,而它恰恰是唯一防止管线自嗨的东西。
