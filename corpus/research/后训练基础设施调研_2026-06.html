后训练(RL Post-Training)基础设施调研

整理日期:2026-06-29 ｜ 数据来源经 bb-browser 实地核实,文末附引用与证据等级 范围:大模型强化学习后训练的基建痛点、训推异步方案、量化证据、成本模型、厂商方案

0. 一句话结论

后训练已从”百亿模型 RLHF”进入 万亿 MoE + 长程 agentic RL 时代。基建的主要矛盾是”效率 vs 策略正确性”:为了让万亿 RL 跑得起所做的每个优化(异步、FP8、独立推理引擎、MoE),都在破坏 RL 算法成立的前提(on-policy、训推同分布)。训推异步主要解决”生成瓶颈导致训练 GPU 空转”,代价是引入 staleness,需用 TIS/router replay 等”赎回正确性”。

1. 最大痛点:生成瓶颈 → GPU 空转

RL 后训练内含一个推理环节:① rollout 生成 → ② 打分 → ③ 训练更新 → 循环。

  • 核心矛盾:同步架构下,生成主导墙钟时间,训练 GPU 空闲。
  • 量化:现代 RL 训练中 rollout 占 >70% 墙钟时间(多篇 2026 论文);32B 模型一个 32K-token batch 的 rollout 可耗时数小时,期间训练卡空转(HF《Keep the Tokens Flowing》)。

衍生痛点:

#痛点本质
1生成瓶颈 / GPU 空转同步下生成与训练串行互等
2训推技术栈割裂推理引擎(vLLM/SGLang)vs 训练引擎(Megatron/FSDP),两套并行与权重布局
3权重同步每步刷新万亿/MoE 权重,传输量巨大
4长尾 / straggler长 CoT 生成长度方差大,超长 rollout 拖垮 batch
5训推数值不一致推理与训练 kernel 算出的 logprob 有偏 → 破坏重要性采样
6资源配比推理/训练 GPU 分配、colocate vs disaggregate
7Agentic RL 放大一切多轮+工具+环境,episode 超长,环境/沙箱(CPU)成新瓶颈

2. 训推异步(disaggregated async)解决了什么

一句话:让昂贵的训练 GPU 不再空等生成。

推理池持续产 rollout → rollout buffer → 训练池持续消费更新权重 → 新权重异步推回推理池

生成与训练时间重叠 → GPU 利用率拉满 → 端到端常见 2–4× 提速。

代价 = off-policy staleness:训练用的是旧策略样本,有偏。异步方案的技术含量在于管理它:

  • bounded staleness(限制样本最多旧几个版本,如 prime-rl 的 max_off_policy_steps)
  • 重要性采样校正 / TIS(截断重要性采样) / CISPO
  • partial rollout(超长生成切片续算,治长尾)
  • router replay(MoE:回放推理路由到训练侧,治训推路由不一致)

HF 七个设计轴:编排原语、buffer 设计、权重同步协议、staleness 管理、partial rollout、LoRA、分布式后端。共识:Ray 主导编排,NCCL broadcast 是权重同步默认,MoE 支持是新分水岭。

5. 厂商方案详解

5.1 MiniMax-M1(让全量 RL 极便宜的范本)

  • 架构:Hybrid MoE,456B 总参 / 45.9B 激活 / 32 专家;混合注意力(每 8 块 1 块 Softmax + 7 块 Lightning 线性注意力)→ 支持百万级上下文。
  • 算法 CISPO(核心贡献):裁剪重要性采样权重而非 token 级更新;报告称比字节 DAPO 快 ~2×,AIME 上优于 DeepSeek GRPO。
  • 系统:512×H800、3 周、$534.7K 跑完全量 RL。
  • 一句话:CISPO(算法省)+ 线性注意力(长上下文省)+ 高效 RL 系统 = 百万上下文全量 RL 压到 50 万美金级。

5.2 prime-rl 0.6.0(万亿 MoE agentic RL)

  • GLM-5 SWE、131k 序列、<5min/步、28×H200 节点。
  • 推理:FP8 + Wide EP + P/D 分离 + KV offloading + router replay;训练:3D 并行(FSDP+EP+CP)+ block-scaled FP8。
  • 去中心化异步;max_off_policy_steps 控 staleness。

5.3 其他

  • verl(字节 Seed,HybridFlow)、AReaL(蚂蚁+清华,全异步)、slime(智谱,GLM-5 用)、ROLL(阿里)、NeMo-RL(NVIDIA)、OpenRLHF、TRL(HF,加 async trainer + delta weight sync)、SkyRL(Berkeley)。
  • 推理后端:SGLang / vLLM;训练后端:Megatron-LM。

5.5 RL 框架的内存与同步机制(谁用了内存池、什么数据进池同步)

“内存池”三层含义:L1 跨节点统一池(KVCache-centric,Mooncake/Dynamo)｜ L2 节点内分层内存(GPU↔CPU offload/备份)｜ L3 逻辑数据缓冲(rollout/replay buffer)。 结论:AReaL/slime/ROLL 主要用 L2+L3,不做 L1;跨节点 KV 池(L1)是底层推理引擎(vLLM/SGLang)或专用平台(Mooncake/Dynamo)的职责。slime 内存管理最精细(SGLang-native)。

数据AReaL(蚂蚁+清华)slime(智谱,SGLang-native)ROLL(阿里)
权重NCCL broadcast + GPU→CPU host offloadRDMA P2P(1T: 53s→7.2s) + pinned CPU backup(sleep/wake)异步 selective broadcast(藏于生成计算后)
rollout/transitionnon-blocking FIFO replay bufferbufferRay 多角色管线 + FP8 减小传输
KV cache交底层引擎隔离 + retention(不 flush radix tree,避 cold-start)offload + memory pooling(集成 vLLM/SGLang)
logprob/reward随 buffer随 buffer随 Ray 管线

洞察:

  1. “进内存池同步”主要是两类数据:权重(训练→推理方向)+ rollout/KV(反向)。
  2. 三者都在做 L2 分层内存(GPU↔CPU offload/备份),但都没自建 L1 跨节点 KV 池——需 Mooncake/Dynamo 专用层。
  3. slime 最接近”池”思维:权重 pinned 备份 + KV 隔离保留 + RDMA P2P,是其支撑 GLM-5(万亿)长程 RL 的内存底座。

6. DeepSeek 成本”几百万美金”的澄清

普遍混淆,拆清:

数字指什么性质
$5.576MDeepSeek-V3 预训练(2.788M H800·时 @$2)⚠️ 预训练,非 RL;即”几百万美金”的出处
$294,000DeepSeek-R1 的 RL(512×H800)✅ R1 强化学习那一步(2025-09 / Nature)
  • 大众记得的”几百万美金训出来” = V3 预训练 $5.5M(且明确不含前期研究/消融/数据成本)。
  • R1 在 V3 之上做 RL 只花 $294K,比预训练便宜一个量级。
  • 结论:前沿模型”那一步 RL”是几十万美金量级;真正贵的是预训练 + 海量前期研发。

7. 2026 H1 最新趋势

  1. 万亿 MoE × agentic RL 落地(prime-rl 0.6.0 / GLM-5 / Kimi-K2.7)。
  2. 训推数值对齐成一等问题(SemiAnalysis “Mind the Gap”):router replay / FP8 对齐 / PipelineRL。
  3. RL-as-a-Service 兴起:Thinking Machines 的 Tinker(托管 RL)。
  4. FP8 全链路(block-scaled)成常态。
  5. 沙箱/CPU 成新瓶颈:agentic RL 要海量代码执行环境(OpenEnv)。
  6. 前沿厂越来越不公开 RL 步数/GPU·时(竞争敏感):GLM-5/V3.2/K2.5 均未披露可比总量。
  7. RL 进入”scaling law 时代”:每代约 10× 算力增长,正逼近并将反超预训练算力占比。 → 详见专题文档:未来RL规模与算力趋势_2026-06.md (核心证据:arXiv:2510.13786 用 >40万 GPU·时证明 RL 可 sigmoid 预测放大;o1→o3 RL 算力约 10× 跃升;R1 的 RL(294K)仅为V3预训练(5.58M)的约 1/19,但增速更快。)
